# 05 MDF (Metadata Framework) — Learning Path

MDF is **how SuccessFactors is extended without code**. It is the platform underneath Position Management, Workflow Configuration, most foundation objects, Benefits, Time Off configuration, and every custom object you will ever build.

This is the folder that turns you from someone who configures what SAP shipped into someone who can build what the customer needs.

| # | File | What you get out of it |
|---|---|---|
| 1 | [MDF fundamentals](01_MDF_Fundamentals.md) | What MDF is, what it replaced, and where it already lives in your instance |
| 2 | [Object definitions](02_Object_Definitions.md) | Creating an object: keys, effective dating, status, security, API visibility |
| 3 | [Fields and field types](03_Fields_and_Field_Types.md) | Every field type, when to use it, and the validation options |
| 4 | [Associations](04_Associations.md) | Valid-values vs composite, multiplicity, and how to model a parent-child object |
| 5 | [Configuration UI and Manage Data](05_Configuration_UI_and_Manage_Data.md) | Designing the screen and maintaining records |
| 6 | [Import, export and versioning](06_MDF_Import_Export_and_Versioning.md) | Bulk loading, moving between tenants, effective-dated records |
| 7 | [MDF security and picklists](07_MDF_Security_and_Picklists.md) | Object-level security, RBP integration, MDF picklists |
| — | [Interview Q&A](Interview_Questions_and_Answers.md) | Questions covering this whole folder |

**Milestone:** build a custom MDF object end to end — fields, an association to a foundation object, a Configuration UI screen, a business rule on one field, bulk data loaded by import, and RBP security — then explain to someone why you did not solve the requirement with a custom field on Job Information instead.
