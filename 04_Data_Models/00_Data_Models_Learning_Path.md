# 04 Data Models — Learning Path

The data models are the **blueprint of the whole instance**: which fields exist, what they are called, who may see them, which picklist they use, and which rules fire on them. Learning to read them is the point at which you stop being a user and start being a consultant.

| # | File | What you get out of it |
|---|---|---|
| 1 | [The data model landscape](01_Data_Model_Landscape.md) | The four models, what each governs, and how to decide which one to open |
| 2 | [Corporate Data Model](02_Corporate_Data_Model.md) | Foundation objects in XML — structure, elements, associations |
| 3 | [Succession Data Model](03_Succession_Data_Model.md) | Employee data and talent background elements in XML |
| 4 | [Country/region-specific data models](04_Country_Specific_Data_Models.md) | CSF-CDM and CSF-SDM — how one instance serves 40 countries |
| 5 | [HRIS elements and fields reference](05_HRIS_Elements_and_Fields_Reference.md) | Every standard element and its fields, as a lookup |
| 6 | [XML syntax and safe editing rules](06_XML_Syntax_and_Editing_Rules.md) | The tags, the attributes, and the habits that stop you breaking an instance |
| 7 | [Business Configuration UI](07_Business_Configuration_UI.md) | Doing all of the above without touching XML |
| 8 | [Picklists](08_Picklists.md) | Picklist Center, external codes, cascading picklists, translations |
| — | [Interview Q&A](Interview_Questions_and_Answers.md) | Questions covering this whole folder |

**Milestone:** open an unfamiliar data-model XML file and explain every element and attribute in it; then add a custom field end to end — model, label, picklist, permission, test, export, document — without help.
